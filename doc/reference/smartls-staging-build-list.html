The brief

The client judges a redesign on richness. Staging currently reads as an empty page with good manners — clean hierarchy, plain-spoken copy, nothing to look at. Shown in that state it reads as a downgrade from the live site, whatever its merits.

The core finding: staging's dullness is not the missing photography. The token system already declares a rich visual vocabulary that never reaches the screen — a brand blue, three elevations, an orange selection glow, a mono face, and four freight-mode colours. Nine of the sixteen items below are just rendering what is already defined. That is why this list needs no palette decision from anyone.

Not changing

  • The palette. Carbon #0a0a0a, orange #ff5a00, the slate 100–900 ramp. Untouched.
  • Colour inheritance. No re-tokening, no renaming, no cascade rework. Every item below consumes existing custom properties.
  • Type pairing. IBM Plex Sans display + Inter body + JetBrains Mono. One defect to fix (P0-3), no substitution.
  • Band structure. The seven-band page stays. Two bands change ground; none are added or removed.
  • The copy. It is the strongest thing on the site. Additions only.

P0 · Broken now

P0Nothing else on this list matters if the client hits one of these in the first minute.
P0-1

Services page renders skeleton loaders forever

Navigating to /services shows grey placeholder bars — an eyebrow, a title, a subtitle, then a card of nine grey pills that never resolve into content.

Where
/services
Fix
Resolve the data source, or render static content for the four service lines already written on the home page. Skeletons must have a terminal state — content, or an empty state with substance (see P1-4).
Accept
No grey pill is on screen two seconds after load, on a cold cache.
P0-2

Hero Track button reads as disabled

The tracking card is the hero's whole proposition, and its button renders in flat light grey with grey label — visually identical to a disabled control. The primary action on the most-seen screen looks dead.

Where
Home hero · "Where is my cargo?" card
Fix
Give it the primary treatment: carbon fill with white label, or orange if it should outrank "Request a quote" (it should not — keep one orange per screen). Reserve the grey for the genuine disabled state, before a reference is typed.
Accept
Empty field → visibly disabled. One character typed → visibly live.
P0-3

Declared body font is not the rendered body font

--brand-font-body declares Inter Variable, Inter, but body computes Public Sans Variable, Public Sans. The type system and the page disagree, so every spacing and measure decision is being made against a face that is not shipping.

Where
body · --brand-font-body
Fix
Pick one deliberately and make both agree. If Public Sans is the intent, update the token; if Inter is, fix whatever overrides body.
Accept
Computed font-family on body resolves to var(--brand-font-body).

P1 · Richness with zero new assets

P1Every item here is buildable today with text, tokens and CSS. This is the tier that wins the meeting.
P1-1

Render the four freight-mode colours

The system defines --mode-sea, --mode-air, --mode-road and --mode-rail and uses none of them. Four service lines, four declared colours, zero on screen — the single largest gap between the system's ambition and its appearance.

Where
Home · services grid · /services cards
Fix
Assign one mode colour per service line and carry it consistently: a 6px top bar on the card, the icon chip tinted at 10–12%, the icon itself at full mode colour, and the "See this service" arrow inheriting it on hover. Same treatment on the service detail pages so a line is recognisable by colour before it is read.
Watch
Orange stays the action colour. Mode colours are identity, never a button.
Accept
Four cards, four distinct colours, orange still the only thing that looks clickable.
P1-2

Replace the repeated placeholder with a designed panel

Four identical 16:9 grey boxes carrying the identical thin cube icon. Repetition is what makes it read unfinished — one empty box is a gap, four is a confession.

Where
Home · services grid · /services cards
Fix
Same 16:9 slot, but composed: a subtle diagonal gradient from the card's mode colour at 8% to transparent, an oversized mode-specific glyph (vessel, stamp, pallet, truck) bled to 55% opacity off the bottom-right corner, and a mono service code top-left — SVC-SEA, SVC-CUS, SVC-WHS, SVC-HTL.
Why it survives
When photography arrives it drops into this exact slot; the code and mode bar stay as overlay furniture. Nothing built here is thrown away.
Accept
Four visibly different panels. No repeated glyph anywhere on the page.
P1-3

Add the proof strip

Staging carries no number, no certification, no network badge, no client mark. The live site carries CBM managed, average clearance time, land-freight distance, ISO 9001, and WCA / FIATA / JC Trans membership. All of that is text and it is already written down.

Where
New row directly beneath the hero, above SERVICES
Fix
Full-width band on carbon: three or four figures set in JetBrains Mono at ~2rem with tabular-nums, uppercase slate labels beneath at --brand-tracking-eyebrow, separated by hairlines at --hero-line. Then a quieter row of credentials — ISO 9001:2015, WCA, FIATA, JC Trans — as bordered pills.
Source
Figures and memberships already published on the live site; confirm currency with the client before they ship.
Accept
A visitor who scrolls one screen has seen a number, a certification and a network name.
P1-4

Turn the empty states into content

"Nothing to show yet — ask us for references instead" is honest and it is a hole in the page. The fix is not better apology copy; it is putting something in the space that does not depend on work being published.

Where
Home · CASE NOTES band · /portfolio · /insights · /careers
Fix
Replace with a corridors panel: origin → destination pairs the firm actually runs (Douala · Kribi · Yaoundé → N'Djamena · Bangui · Libreville · Malabo), each row carrying its mode colour, transit indication and a customs note. Add a sectors row — energy, humanitarian, construction, pharma — as bordered chips.
Second choice
If corridor data is not to hand: a single anonymised operation written as a case note ("Out-of-gauge transformer, Douala → N'Djamena") reads as proof and needs no client sign-off on names.
Accept
No band on the site says a version of "nothing here yet".
P1-5

Break the band monotony with one carbon section

Seven bands alternate #ffffff and #f7f8f8 — a 3% difference — each divided by the same hairline. After the hero, the page never changes register again, so scrolling produces no events.

Where
CLIENT PORTAL band (best candidate) · optionally HOW IT WORKS
Fix
Flip the portal band to --brand-carbon with --hero-foreground text and --hero-line rules — tokens the hero already uses, so no new values. The portal mock's orange status ticks gain enormous contrast on carbon, and the page acquires a mid-scroll landmark.
Watch
One dark band, not two. Two makes the page striped rather than punctuated.
Accept
Thumbnail of the full page shows three distinct grounds, not two near-identical ones.
P1-6

Spend the elevation tokens

Three shadows are defined — --shadow-s, -m, -l — and the page renders flat: cards are outlines. Depth is the cheapest richness there is and it is already sitting in the stylesheet.

Fix
Assign a scale and hold it: --shadow-s for resting cards, --shadow-m on hover with a 1–2px lift over --dur/--ease, --shadow-l reserved for the two hero-level objects (the tracking card and the portal mock).
Accept
Three distinguishable elevations on the home page; hovering a service card visibly changes it.
P1-7

Lift the hero photograph out of the dark

The hero already loads an image. It is crushed to near-invisibility under the carbon overlay — the site is paying the bandwidth for a photo nobody can see.

Fix
Reduce the overlay to a directional scrim: near-opaque carbon behind the headline column, falling to roughly 55% across the right two-fifths so the crane and container stack read. Keep white-on-carbon contrast where the type actually sits.
Accept
Subject identifiable at a glance on a phone; headline contrast unchanged.
P1-8

Use mono as texture, not just as a placeholder

The single most product-feeling detail on the whole site is the mono reference SBL-OPS-2026-0142 in the tracking field. That texture appears exactly once.

Fix
Set every machine-shaped value in --brand-font-mono: file references, service codes, proof figures, dates, transit times, status codes in the portal mock, the reference the contact form promises. Sizes at .78–.82rem with tabular-nums wherever digits stack.
Why
It is what makes an operations firm look like it runs systems rather than a phone. Free, and orthogonal to imagery.
Accept
Mono appears in at least four distinct places per page.
P1-9

Let the portal mock break its band

Everything on the page sits obediently inside its band. Nothing overlaps, so the page has no foreground and background — just a stack.

Fix
Pull the portal mock card up so it crosses the boundary into the band above by 40–60px, carrying --shadow-l. On mobile, drop the overlap and keep the shadow.
Accept
One deliberate overlap on the home page. Exactly one — the device stops working if repeated.

P2 · Motion

P2The live site rewards scrolling; staging does not move. Six reveal-tagged elements exist — use them properly and add two set-pieces.
P2-1

Count the proof figures up

The live site's stat counters are the single most-noticed animation on it. Once P1-3 ships, staging has the numbers to do the same.

Fix
Trigger on intersection, once, ~900ms ease-out, tabular-nums so the width does not jitter. Honour prefers-reduced-motion by rendering the final value immediately.
Accept
Figures animate on first view only; never re-run on scroll-back.
P2-2

Animate the shipment timeline

The portal mock — File opened → Vessel departed → Customs cleared → Delivery scheduled — is the best-looking object on the site and it is completely static.

Fix
On entering view, stagger the three completed ticks in at ~120ms intervals, then leave the fourth pulsing gently on its orange ring. It demonstrates the product in three seconds without a screenshot.
Accept
Plays once per page load; reduced-motion renders the completed state.
P2-3

Give reveals a real cadence

Six elements carry reveal hooks on a 7,900px page, and --dur is .15s — too fast to register as motion.

Fix
Extend reveals to every band's heading block and card grid, at ~400ms with a 60–80ms stagger across siblings, translateY 12–16px. Keep --dur at .15s for interaction feedback — these are different jobs and should not share a token.
Accept
Every band announces itself once; no element animates twice.

P3 · When the images land

P3Nothing here blocks the client review. Written down so the P1 work is built to receive it.
P3-1

Photography drops into slots that already exist

Every P1 item is additive to imagery rather than replaced by it — that is the point of building them first.

Slots
4 × 16:9 service panels · 1 hero · 1 portal band · 3–4 corridor thumbnails
Treatment
Mode bar stays above the photo; service code stays as overlay furniture; the gradient becomes a scrim at the same angle. Shoot list: vessel or port gantry, a customs counter, bonded racking, a truck on the N'Gaoundéré road.
Accept
Adding a photo changes no layout dimension.

Order of work

  • Day 1 — P0. Services skeletons, Track button, font token. Nothing is demoable until these are gone.
  • Day 2 — P1-1, P1-2. Mode colours and designed panels. This is the change that reads as "a designer touched it" in a thumbnail.
  • Day 3 — P1-3, P1-4. Proof strip and corridors. This is the change that reads as "a real firm".
  • Day 4 — P1-5 to P1-9. Carbon band, elevations, hero scrim, mono texture, the overlap. Half a day each at most.
  • Day 5 — P2. Motion, then a pass on a real phone before it goes in front of anyone.

Show the client after Day 3 at the earliest. Before that, the mode colours are landed but the page still has no proof in it, and proof is what he is actually buying.
